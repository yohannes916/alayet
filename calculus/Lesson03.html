Lesson 3 — Slicing Curves into Rectangles

Left Sums, Right Sums, and the Sandwich · Intuitive Calculus for a Curious Student · Lesson 3 of 20

📚 All lessons← Lesson 2Next: Lesson 4 →
🎯 Goal of this lesson: rectangles handled flat graphs, triangles handled straight slanted graphs — but a genuinely curved graph fits neither. Today you learn the single most important trick in integration: slice the region into skinny rectangles, get an estimate from the left edges and another from the right edges, and trap the true answer between them.

1 The problem — curves fit no shape we know

  • Suppose a car's speed is v = t2 — after 1 second it moves at 1 m/s, after 2 seconds at 4 m/s. The speed doesn't climb steadily; it climbs faster and faster. The graph is a curve that bends upward.
  • From Lesson 2 we know the distance is the area under this graph… but no rectangle fits under a curve exactly, and no triangle does either — a triangle has a straight top, and this top bends.
  • Geometry class has no formula for "area under a bendy line." We need a completely new strategy.

2 The trick — slice it and pretend

  • Chop the time interval into slices, and PRETEND the rate is constant within each slice. Each slice becomes a skinny rectangle — and rectangles we can do!
  • Is the pretending a lie? A small one. Within a half-second slice the speed only changes a little, so a flat-topped rectangle is close to the truth. The total of all the rectangle areas is an estimate of the true area.
  • Every rectangle's area = (slice width) × (the height we picked for it). The whole game is: which height do we pick for each slice?

3 LEFT estimate vs RIGHT estimate

  • LEFT estimate: give each rectangle the curve's height at the slice's starting (left) edge.
  • RIGHT estimate: give each rectangle the curve's height at the slice's ending (right) edge.
  • For a graph that is increasing (always climbing): the left edge is the LOWEST point of each slice, so every left rectangle sits under the curve → the left sum is an underestimate. The right edge is the HIGHEST point, so every right rectangle pokes above the curve → the right sum is an overestimate.
  • So the true area is sandwiched: left sum ≤ true area ≤ right sum. We may not know the exact answer yet, but we can trap it!
  • (For a decreasing graph it flips: left = overestimate, right = underestimate. The sandwich still works, just with the bread swapped.)

4 Full worked example — area under y = x² from 0 to 2

Setup: estimate the area under y = x² from x = 0 to x = 2, using 4 slices. Each slice's width = (2 − 0) ÷ 4 = 0.5. The slice edges are at x = 0, 0.5, 1, 1.5, 2. The curve's heights there:
x = 0 → 0² = 0  ·  x = 0.5 → 0.5² = 0.25  ·  x = 1 → 1² = 1  ·  x = 1.5 → 1.5² = 2.25  ·  x = 2 → 2² = 4

LEFT sum (heights at each slice's left edge: 0, 0.5, 1, 1.5):
0.5 × (0² + 0.5² + 1² + 1.5²) = 0.5 × (0 + 0.25 + 1 + 2.25) = 0.5 × 3.5 = 1.75

RIGHT sum (heights at each slice's right edge: 0.5, 1, 1.5, 2):
0.5 × (0.5² + 1² + 1.5² + 2²) = 0.5 × (0.25 + 1 + 2.25 + 4) = 0.5 × 7.5 = 3.75

The sandwich: since y = x² is increasing here, the true area is trapped: 1.75 < true area < 3.75. The exact answer (you'll be able to compute it yourself in Lesson 8!) is 8/3 ≈ 2.67 — and sure enough, 2.67 sits right inside the sandwich. ✓

5 More slices = a better estimate

  • With 4 slices, our sandwich was wide: from 1.75 to 3.75. Why so sloppy? Because each rectangle's flat top misses the curve by a visible gap.
  • Use more, skinnier slices and each rectangle only has to "pretend" over a tinier stretch — the staircase of rectangle tops hugs the curve more closely, and the left and right sums squeeze toward each other:

  • Both sums are marching toward the same number: 8/3 ≈ 2.6667. The sandwich is closing, and the true area has nowhere to hide.

6 The big reveal — what integration actually IS

  • Keep slicing forever: 1000 slices, a million, more… As the slices get infinitely skinny, the left and right sums squeeze together onto a single number. That number is the exact area — no estimate, no error, none.
  • THAT is integration: the exact total you get when the slice-and-add estimate is pushed to infinitely skinny slices. The famous integral sign ∫ is literally a stretched-out letter S, for "sum" — a sum of infinitely many, infinitely skinny rectangles.
  • You now understand what the symbol ∫02 x2 dx means: "the exact area under x² from 0 to 2." The next lessons build the shortcut for computing it without adding a million rectangles.
✏️ Exercises — 20 problems (write your answer on paper, then reveal)
1.left sum from a table
Water flows into a tub at an increasing rate. Measurements, one minute apart:
t = 0: 2 L/min · t = 1: 4 L/min · t = 2: 6 L/min · t = 3: 8 L/min · t = 4: 10 L/min.
Estimate the total water from t = 0 to t = 4 with a LEFT sum using 4 slices of width 1 minute.

Worked solution

Background: between measurements we don't know the rate, so we PRETEND it stays at the value measured at the start (left edge) of each minute. Each minute becomes a rectangle of width 1; total water ≈ sum of (rate at left edge) × 1. The interval 0-to-4 has 4 slices, so a left sum uses the first 4 measurements — the t = 4 reading is never a left edge.
Slices: 0→1 uses rate 2; 1→2 uses rate 4; 2→3 uses rate 6; 3→4 uses rate 8.
Left sum = 1 × (2 + 4 + 6 + 8) = 20.
≈ 20 liters (an underestimate, since the rate is increasing)
2.right sum from a table
Using the same table as #1 (rates 2, 4, 6, 8, 10 L/min at t = 0, 1, 2, 3, 4), estimate the total water from t = 0 to t = 4 with a RIGHT sum.

Worked solution

Background: a right sum pretends each minute's rate is the value at the END (right edge) of that minute. So now the first reading (t = 0) is skipped and the last one (t = 4) gets used. Same four slices, different pretend heights.
Slices: 0→1 uses rate 4; 1→2 uses rate 6; 2→3 uses rate 8; 3→4 uses rate 10.
Right sum = 1 × (4 + 6 + 8 + 10) = 28.
Sandwich: the true total is somewhere between 20 (left) and 28 (right).
≈ 28 liters (an overestimate; truth is between 20 and 28)
3.left sum · formula
Estimate the area under the line y = 2x from x = 0 to x = 2 using a LEFT sum with 2 slices of width 1. (First find the heights: y at x = 0 and at x = 1.)

Worked solution

Background: when the graph comes from a formula, you compute the heights yourself by plugging in x-values. y = 2x means "the height at any x is double the x." The slice edges here are x = 0, 1, 2; a left sum uses the heights at x = 0 and x = 1.
Heights: at x = 0, y = 2 × 0 = 0. At x = 1, y = 2 × 1 = 2.
Left sum = 1 × (0 + 2) = 2.
Left sum = 2
4.right sum + sandwich
Same setup as #3 (y = 2x from 0 to 2, two slices of width 1). (a) Compute the RIGHT sum. (b) The region under y = 2x from 0 to 2 is a triangle — compute its TRUE area with ½ × base × height, and check it lands between your two estimates.

Worked solution

Background: this problem lets you CATCH the sandwich in the act, because for a straight line we can also get the exact area with Lesson 2's triangle formula. The left/right estimates should trap it.
(a) Right-edge heights: at x = 1, y = 2; at x = 2, y = 4. Right sum = 1 × (2 + 4) = 6.
(b) True area: triangle with base 2 and height 4 → ½ × 2 × 4 = 4.
Sandwich check: left 2 < true 4 < right 6 ✓ — and 4 is exactly in the middle (a straight-line special treat; see #20).
(a) Right sum = 6   (b) True area = 4, safely between 2 and 6
5.over or under?
A runner's speed graph is INCREASING the whole time (she keeps speeding up). Without computing anything: does a LEFT sum overestimate or underestimate her true distance? Explain why in a sentence.

Worked solution

Background: on an increasing graph, the left edge of every slice is the slice's LOWEST point — the curve only climbs from there. So each left rectangle uses the smallest height available in its slice and fits entirely under the curve.
Every left rectangle is shorter than the curve everywhere else in its slice, so the rectangles miss some area under the curve.
Therefore the left sum comes out SMALLER than the truth: an underestimate. (In running terms: pretending each stretch was run at its starting speed short-changes a runner who's speeding up.)
Underestimate — each left rectangle sits completely below the rising curve
6.slice width
You want to estimate an area from t = 1 to t = 4 using 6 equal slices. How wide is each slice, and at what t-values are the slice edges?

Worked solution

Background: slice width = (length of the whole interval) ÷ (number of slices), and the interval's length is end − start — NOT just the end value. Getting the width right is step zero of every slicing problem.
Interval length = 4 − 1 = 3. Width = 3 ÷ 6 = 0.5.
Edges: start at 1 and step by 0.5 → t = 1, 1.5, 2, 2.5, 3, 3.5, 4. (Seven edges make six slices — always one more edge than slices.)
Width = 0.5; edges at t = 1, 1.5, 2, 2.5, 3, 3.5, 4
7.left sum · y = x + 1
Estimate the area under y = x + 1 from x = 0 to x = 2 with a LEFT sum using 4 slices of width 0.5.

Worked solution

Background: y = x + 1 means "height = the x-value plus one." With width 0.5 the edges are x = 0, 0.5, 1, 1.5, 2; a left sum uses the first four. Recipe: width × (sum of left-edge heights).
Left heights: x = 0 → 1; x = 0.5 → 1.5; x = 1 → 2; x = 1.5 → 2.5.
Sum of heights = 1 + 1.5 + 2 + 2.5 = 7.
Left sum = 0.5 × 7 = 3.5.
Left sum = 3.5
8.right sum · y = x + 1
Same setup as #7 (y = x + 1 from 0 to 2, four slices of width 0.5). (a) Compute the RIGHT sum. (b) The exact area (a trapezoid: rectangle of height 1 plus a triangle, Lesson 2 style) is 4 — check the sandwich.

Worked solution

Background: right sum = width × (sum of right-edge heights): skip the first edge, include the last. And the exact check: rectangle 1 × 2 = 2 plus triangle ½ × 2 × 2 = 2 gives 4, our Lesson 2 method.
(a) Right heights: x = 0.5 → 1.5; x = 1 → 2; x = 1.5 → 2.5; x = 2 → 3. Sum = 9.
Right sum = 0.5 × 9 = 4.5.
(b) Sandwich: left 3.5 < true 4 < right 4.5 ✓.
(a) Right sum = 4.5   (b) 3.5 < 4 < 4.5 — the sandwich holds
9.car data · left sum
A car's speedometer is read every 2 seconds while it accelerates:
t = 0 s: 3 m/s · t = 2 s: 5 m/s · t = 4 s: 6 m/s · t = 6 s: 10 m/s.
Estimate the distance traveled from t = 0 to t = 6 with a LEFT sum (3 slices of width 2).

Worked solution

Background: this is how real GPS units and fitness trackers estimate distance — they only get speed readings every so often, and they assume the speed held steady between readings. Note the slice width is 2 here (readings are 2 s apart), so each rectangle is rate × 2.
Left edges: rates 3, 5, 6 (the t = 6 reading is not a left edge).
Left sum = 2 × (3 + 5 + 6) = 2 × 14 = 28.
≈ 28 meters (underestimate — the car is speeding up)
10.car data · right sum + sandwich
Using the same speed table as #9, (a) compute the RIGHT sum, and (b) write one sentence saying what you now know about the car's TRUE distance.

Worked solution

Background: with both sums in hand, you can make a guarantee about the truth without ever knowing the exact speeds between readings. Since the speeds are increasing, left is too small and right is too big — the truth is pinned between them. This "trap the answer" style of thinking is a superpower in science, where data always comes in samples.
(a) Right edges: rates 5, 6, 10. Right sum = 2 × (5 + 6 + 10) = 2 × 21 = 42.
(b) The true distance is somewhere between 28 and 42 meters — guaranteed, as long as the speed never dipped between readings.
(a) 42 meters   (b) true distance is trapped between 28 m and 42 m
11.y = x² · 2 slices
Estimate the area under y = x2 from x = 0 to x = 2 using just 2 slices of width 1. Compute BOTH the left sum and the right sum.

Worked solution

Background: y = x² means "height = x times itself": at x = 0, 1, 2 the heights are 0, 1, 4. Only two fat slices this time — compare your sandwich to the lesson's 4-slice sandwich (1.75 to 3.75) to see how much fatter slices make a sloppier trap.
Left sum (heights at x = 0 and 1): 1 × (0 + 1) = 1.
Right sum (heights at x = 1 and 2): 1 × (1 + 4) = 5.
Sandwich: 1 < true area < 5. (With 4 slices it tightened to 1.75–3.75; the true answer is 8/3 ≈ 2.67.)
Left = 1, Right = 5
12.decreasing graph
A bathtub is draining, and the outflow rate is DECREASING the whole time (water leaves fast at first, then slower as the tub empties). For estimating the total water drained: which is the overestimate, the left sum or the right sum? Explain.

Worked solution

Background: everything flips for a decreasing graph. Now each slice's LEFT edge is its HIGHEST point (the rate only drops from there), so left rectangles poke above the curve; right rectangles hide below it. The rule isn't "left = under" — it's "the edge where the graph is taller gives the overestimate."
Left edges catch the rate at its biggest moment in each slice → left rectangles are too tall → LEFT sum is the overestimate.
Right edges catch the smallest rate in each slice → RIGHT sum is the underestimate. The truth is still sandwiched between them.
Left sum overestimates; right sum underestimates (the reverse of an increasing graph)
13.y = 2x · 4 slices + check
For y = 2x from x = 0 to x = 4, with 4 slices of width 1: (a) compute the left sum, (b) compute the right sum, (c) compute the TRUE area (it's a triangle!), and (d) confirm the sandwich.

Worked solution

Background: heights of y = 2x at the edges x = 0, 1, 2, 3, 4 are 0, 2, 4, 6, 8. The true region is a triangle with base 4 and height 8, so Lesson 2's formula gives us the exact answer to test the estimates against.
(a) Left sum = 1 × (0 + 2 + 4 + 6) = 12.
(b) Right sum = 1 × (2 + 4 + 6 + 8) = 20.
(c) True area = ½ × 4 × 8 = 16.
(d) 12 < 16 < 20 ✓ — and again the truth is exactly halfway between (straight lines do that).
(a) 12   (b) 20   (c) 16   (d) 12 < 16 < 20 ✓
14.sandwich logic
For an increasing rate graph, your left sum is 14 and your right sum is 22. Your friend announces "the true total is 25." Without knowing anything else about the graph, how do you know your friend is wrong? What CAN you say about the true total?

Worked solution

Background: the sandwich isn't a vibe — it's a guarantee. For an increasing graph, every left rectangle fits fully under the curve (left sum too small) and every right rectangle fully covers it (right sum too big). No true area can escape those bounds.
The truth must satisfy: 14 ≤ true total ≤ 22.
25 is bigger than the overestimate 22 — impossible. Even the too-generous right sum only reached 22.
What we can say: the true total is between 14 and 22. Without more slices, that's the honest limit of our knowledge.
25 lies outside the sandwich [14, 22], so it's impossible; the truth is between 14 and 22
15.half-width slices
A sprinter's speed is measured every HALF second:
t = 0: 1 m/s · t = 0.5: 2 m/s · t = 1: 4 m/s · t = 1.5: 7 m/s · t = 2: 11 m/s.
Estimate her distance from t = 0 to t = 2 with (a) a left sum and (b) a right sum. Careful: the slice width is 0.5, not 1!

Worked solution

Background: when readings are half a second apart, each rectangle is only 0.5 wide, so each contributes (rate × 0.5). Forgetting to multiply by the width is the #1 slicing error — a sum of raw rates has the wrong units entirely (it would be m/s, not meters).
(a) Left edges: 1, 2, 4, 7. Left sum = 0.5 × (1 + 2 + 4 + 7) = 0.5 × 14 = 7.
(b) Right edges: 2, 4, 7, 11. Right sum = 0.5 × (2 + 4 + 7 + 11) = 0.5 × 24 = 12.
True distance: between 7 and 12 meters (speeds are increasing).
(a) 7 meters   (b) 12 meters
16.interval not starting at 0
Estimate the area under y = x2 from x = 1 to x = 3 using 2 slices of width 1. Compute both the left and right sums.

Worked solution

Background: nothing says slicing must start at 0! The interval is 1 to 3, so the edges are x = 1, 2, 3, and the heights there are 1² = 1, 2² = 4, 3² = 9. Same recipe: width × (sum of chosen heights).
Left sum (heights at x = 1 and 2): 1 × (1 + 4) = 5.
Right sum (heights at x = 2 and 3): 1 × (4 + 9) = 13.
The true area (Lesson 8 will confirm) is 26/3 ≈ 8.67 — inside the sandwich 5 to 13 ✓.
Left = 5, Right = 13
17.challenge · average the sums
In the lesson's worked example (y = x² from 0 to 2, four slices), the left sum was 1.75 and the right sum was 3.75. (a) Compute the AVERAGE of the two sums. (b) The true area is 8/3 ≈ 2.67. How close is your average — and why would averaging be a smart move in general?

Worked solution

Background: if one estimate is guaranteed too small and the other guaranteed too big, meeting in the middle should cancel most of the error. (Averaging left and right is secretly the same as using trapezoids instead of rectangles — mathematicians call it the "trapezoid rule.")
(a) Average = (1.75 + 3.75) ÷ 2 = 5.5 ÷ 2 = 2.75.
(b) True ≈ 2.67. The average misses by only about 0.08 — compare that to the left sum missing by ≈ 0.92 and the right by ≈ 1.08. One tiny idea bought us a 10× better estimate!
(a) 2.75   (b) off by only ≈ 0.08 — averaging cancels most of the over/under error
18.concept · why more slices?
In your own words (2–3 sentences): WHY does using more, skinnier slices make the rectangle estimate better? Mention what happens to the gap between the staircase and the curve.

Worked solution

Background: the error in each slice comes from the lie we told — "the rate is constant here." The lie's size depends on how much the curve actually changes within one slice. Skinnier slice → less change inside it → smaller lie.
Sample answer: "Each rectangle is wrong only where its flat top misses the curve. If a slice is skinny, the curve barely has room to rise or fall inside it, so the flat top stays very close to the curve. With more and more skinny slices, the staircase of tops hugs the curve tighter and tighter, and the total error shrinks toward zero."
Evidence from the lesson's table: 4 slices → sandwich gap of 2; 1000 slices → gap of 0.008.
Skinnier slices mean the curve changes less within each one, so every flat top lies closer to the curve and the total error shrinks toward zero
19.challenge · decreasing data
A pot of hot cocoa is cooling, losing heat at a decreasing rate:
t = 0: 10 units/min · t = 1: 8 · t = 2: 5 · t = 3: 3 · t = 4: 2 (units of heat per minute).
For the total heat lost from t = 0 to t = 4 (width-1 slices): (a) compute the left sum, (b) compute the right sum, (c) label each one over- or underestimate, and (d) give the sandwich for the true total.

Worked solution

Background (physics): hot things cool fastest when they're hottest — as the cocoa approaches room temperature, heat leaks out slower and slower, so this rate graph DECREASES. That flips the roles: left edges are the tall ones now, so the left sum is the overestimate.
(a) Left sum = 1 × (10 + 8 + 5 + 3) = 26.
(b) Right sum = 1 × (8 + 5 + 3 + 2) = 18.
(c) Decreasing graph → left = OVERestimate, right = UNDERestimate.
(d) Sandwich: 18 ≤ true heat lost ≤ 26.
(a) 26   (b) 18   (c) left over, right under   (d) truth between 18 and 26 units
20.challenge · when the average is PERFECT
For the straight line y = 2x from x = 0 to x = 2 with 2 slices (from #3 and #4): the left sum was 2, the right sum was 6, and the true area was 4. (a) Average the left and right sums. (b) You should hit the true area EXACTLY. Explain why averaging is perfect for straight lines but only approximately right for curves like x².

Worked solution

Background: averaging the left and right rectangle in each slice is the same as replacing the rectangle with a trapezoid whose slanted top connects the curve's two edge points. If the graph IS a straight line, that slanted top lies exactly ON the graph — zero error. If the graph curves, the straight top misses it slightly (for x², which bends upward, the straight top sits a hair above the curve).
(a) Average = (2 + 6) ÷ 2 = 4. Exactly the true area ✓.
(b) In each slice, averaging left and right heights builds a trapezoid whose top is a straight segment between two points on the graph. A straight line graph passes through both points AND every point between — perfect match. A curve like x² touches the segment only at its two ends and sags below it in between, so a small (but only small!) error survives — which is why the average 2.75 in #17 was close to 8/3 but not exact.
(a) Average = 4 = the exact area   (b) the trapezoid's straight top lies exactly on a straight-line graph, but only near a curved one
